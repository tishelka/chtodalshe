# Проверки ЧтоДальше

## Команды

```sh
npm run check
npm run backend:lint
npm run backend:test
npm run test:e2e
npm run export:native
npx expo-doctor
```

Для браузерных тестов установите Chromium через `npx playwright install chromium`. Для серверных и браузерных проверок нужны PostgreSQL, Python-окружение backend, зависимости из `requirements-dev.txt` и роль с правом создания базы.

По умолчанию подключение берётся из `backend/.env`. Другой сервер можно задать переменной `TEST_DATABASE_URL`. Оба набора проверок создают базу `whatnext_test_<случайный UUID>`, выполняют настоящие миграции и seed. После завершения удаляется только созданная ими база. Рабочая база не очищается.

## TypeScript

`npm run check` выполняет TypeScript strict, ESLint, Vitest и сравнение каталогов.

- Рекомендации: обязательные условия, рейтинг по интересам и настроению, пустая выдача, завершение серии, отсутствие повторов, детерминированный RNG.
- Каталог: 70 уникальных занятий, 10 категорий, сетка сочетаний условий.
- HTTP: загрузка без регистрации и токенов, GET/PUT/PATCH/DELETE, повторная загрузка с сервера, пагинация, валидация ответов, ошибки, тайм-аут и отмена запросов.
- Браузерный fetch вызывается без неверной привязки к экземпляру класса.

## FastAPI и PostgreSQL

`npm run backend:test` проверяет:

- Health, каталог, карточку и JSON camelCase.
- Общий профиль создан миграцией; запросы работают без авторизации.
- Настройки, избранное, история и выбранный план сохраняются.
- Другой клиент и новый экземпляр API видят те же данные.
- Некорректные фильтры, категории, даты, UUID и лишние поля отклоняются.
- Повторное сохранение не создаёт дубликатов и не снимает отметку выбора.
- Порядок и пагинация истории, повтор одного занятия.
- Очистка истории сохраняет интересы и избранное.
- Повтор миграций и seed сохраняет данные.
- Обновление прежней схемы сохраняет старые профили и их данные.
- Реальные ограничения PostgreSQL, CORS и ответ 503 при недоступной базе.

SQLite и фиктивный SQL-движок не используются.

## Браузер

`npm run test:e2e` создаёт отдельную базу, запускает временный FastAPI на свободном порту, экспортирует приложение и выполняет Playwright на мобильном размере Chromium. После проверки API останавливается, тестовая база удаляется. Временная web-сборка находится в `.tools/ui-test-dist`, лог API — `.tools/e2e-api.log`.

Сценарии:

1. Полный путь: интересы, фильтры, подбор, «Другое», избранное, выбранный план, история, перезагрузка, повтор условий и сюрприз. HTTP-запросы подтверждают записи в базе.
2. Пропуск интересов, границы участников, пустая выдача и изменение условий.
3. Сохранение интересов и очистка истории с подтверждением.
4. Исчерпание серии и перезапуск.
5. Ошибка записи избранного и успешный повтор.
6. Сервер сохранил историю, но ответ потерялся: повтор не создаёт дубликат.
7. Недоступный API и восстановление после повторного запроса.
8. Экран 320 px без горизонтального переполнения.
9. Вкладки, карточка, удаление избранного и возврат в форму.
10. Работа при отключённом локальном хранилище браузера; другой браузер видит общий профиль, запросы не содержат токенов.

Каждый сценарий начинает с пустого общего профиля в отдельной тестовой базе. Прямой запуск Playwright без тестового окружения отклоняется, чтобы случайно не очистить рабочий профиль.

## Ручная проверка

- Запустить API/PostgreSQL и открыть `/health`, `/docs`.
- Указать адрес API для телефона или эмулятора, пройти интересы.
- Задать 3 участника, 2 часа, 500 ₽, дома, спокойное настроение.
- Проверить «Другое», избранное, историю, выбранный план и повтор условий.
- Закрыть приложение и открыть снова: данные загружаются из PostgreSQL.
- Открыть другое устройство: оно видит общий профиль.
- Проверить системный возврат Android, жест iOS и увеличенный шрифт.
- Остановить API, убедиться, что приложение показывает ошибку и повтор.

JS/Hermes-экспорт Android/iOS не заменяет установку APK/IPA на устройство. Docker-контейнеры и физические устройства в текущем окружении не проверялись; backend проверяется с отдельным локальным PostgreSQL.
