# Контракт ЧтоДальше API

Сервер: FastAPI + SQLAlchemy + PostgreSQL. Интерактивная документация находится по `/docs`, спецификация — `/openapi.json`.

JSON использует camelCase, совпадающий с TypeScript-моделями приложения. Python и база используют snake_case. Конвертация выполняется моделями Pydantic.

## Маршруты

| Метод  | Путь                          | Доступ    | Ответ                                               |
| ------ | ----------------------------- | --------- | --------------------------------------------------- |
| GET    | `/health`                     | Публичный | `{"status":"ok"}`; 503 при недоступной БД           |
| POST   | `/sessions/anonymous`         | Публичный | 201, `accessToken`, `tokenType`, `userId`           |
| GET    | `/activities`                 | Публичный | Массив Activity                                     |
| GET    | `/activities/{id}`            | Публичный | Одна Activity или 404                               |
| GET    | `/me/preferences`             | Bearer    | Preferences                                         |
| PUT    | `/me/preferences`             | Bearer    | 204                                                 |
| GET    | `/me/favorites`               | Bearer    | Массив UUID занятий                                 |
| PUT    | `/me/favorites/{activity_id}` | Bearer    | 204; повтор не создаёт дубликат                     |
| DELETE | `/me/favorites/{activity_id}` | Bearer    | 204, включая повтор удаления                        |
| GET    | `/me/history`                 | Bearer    | Массив HistoryEntry от новых к старым               |
| PUT    | `/me/history/{id}`            | Bearer    | 204; повтор не создаёт дубликат и не снимает chosen |
| PATCH  | `/me/history/{id}`            | Bearer    | 204; тело `{"chosen":true}`                         |
| DELETE | `/me/history`                 | Bearer    | 204; очищает историю только текущего пользователя   |

Списки принимают `offset >= 0` и `limit` от 1 до 500, по умолчанию 100. Каталог включает архивные записи, чтобы можно было открыть старое избранное и историю; алгоритм не рекомендует записи с `isActive: false`.

## Анонимная сессия

Клиент выполняет `POST /sessions/anonymous` один раз при отсутствии сохранённой сессии. Сервер создаёт пользователя и случайный токен из 32 криптографически случайных байтов. В PostgreSQL сохраняется только SHA-256 токена. Клиент отправляет:

```http
Authorization: Bearer <accessToken>
```

Пользователь определяется сервером по токену. Клиент не передаёт `userId` в запросах личных данных. Все чтения, изменения и удаления ограничены текущим user_id. Ошибка авторизации — 401; новый аккаунт автоматически вместо прежнего не создаётся.

В MVP сессия действует до удаления серверной записи. Отозвать её можно удалением соответствующего `user_sessions` или пользователя. Постоянных аккаунтов и восстановления после потери токена нет. Для опубликованного сервиса API должен работать через HTTPS.

## Настройки

```json
{
  "interests": ["board_games", "walks"],
  "onboardingCompleted": true,
  "lastFilters": {
    "participants": 3,
    "availableMinutes": 120,
    "budgetPerPerson": 500,
    "location": "home",
    "mood": "calm"
  }
}
```

`lastFilters` может быть `null`. Список интересов может быть пустым; дубликаты удаляются. Числовой `null` в фильтрах означает отсутствие ограничения. Участники — от 1 до 10, время положительное, бюджет неотрицательный. Места: `home`, `outdoors`, `venue`, `any`; настроения: `calm`, `active`, `social`, `creative`, `any`.

## История

```json
{
  "id": "30000000-0000-4000-8000-000000000001",
  "activityId": "10000000-0000-4000-8000-000000000001",
  "createdAt": "2026-10-12T12:00:00Z",
  "filters": {
    "participants": 1,
    "availableMinutes": null,
    "budgetPerPerson": null,
    "location": "any",
    "mood": "any"
  },
  "chosen": false
}
```

ID записи в теле должен совпадать с адресом PUT. Дата должна содержать часовой пояс и нормализуется в UTC. Одна активность может иметь несколько записей истории. UUID записи уникален внутри пользователя; одинаковый клиентский UUID не позволяет изменить чужую историю.

## Ошибки

- 401 — отсутствующий или недействительный токен.
- 404 — занятие или собственная запись истории не найдены.
- 422 — неверные значения, неизвестные поля, UUID или формат даты.
- 409 — нарушено ограничение базы.
- 503 — база временно недоступна.

Ответ содержит `detail` с понятным сообщением. SQL, параметры соединения и stack trace клиенту не возвращаются. Полученный 401 не удаляет локальный токен и не создаёт новую сессию автоматически.
