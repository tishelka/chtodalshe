# Проверки ЧтоДальше

## Команды

```sh
npm run check
npm run backend:lint
npm run backend:test
npm run test:e2e
npm run test:remote-ui
npm run export:native
npx expo-doctor
```

Для браузерных тестов установите Chromium через `npx playwright install chromium`. Для серверных тестов нужен работающий PostgreSQL, виртуальное окружение backend и зависимости из `requirements-dev.txt`.

## TypeScript

- Исходные сценарии рекомендаций: жёсткие ограничения, scoring, интересы, настроение, пустая выдача, завершение серии, отсутствие повторов, десятка кандидатов, детерминированный RNG, неизменяемость каталога.
- Каталог: 70 уникальных занятий в 10 категориях, корректность данных, пример ТЗ, сетка 400 сочетаний ограничений.
- Локальное хранение: избранное без дубликатов, конкурентные записи, восстановление интересов и истории, повтор условий, ошибка записи, повреждённые данные без перезаписи.
- HTTP-репозиторий: публичный каталог, анонимная сессия, Bearer для личных данных, одна сессия при параллельных запросах, восстановление токена, раздельные адреса серверов, PUT/PATCH/DELETE, пагинация, валидация ответов, тайм-аут, ошибки сервера и отсутствие неявного восстановления аккаунта после 401.
- Отдельная проверка правильного вызова браузерного fetch без привязки к объекту репозитория.

`npm run check` выполняет TypeScript strict, ESLint, Vitest и сравнение исходного и серверного каталога.

## Настоящий FastAPI / PostgreSQL

`backend:test` создаёт отдельную базу `whatnext_test_<случайный UUID>`, выполняет Alembic и загружает каталог. После тестов удаляется только созданная тестом база. Рабочая база не очищается; SQLite или фиктивный SQL-движок не используются.

Проверяются:

- Health, публичный каталог, получение карточки и формат camelCase.
- Создание анонимной сессии, хранение хеша вместо токена и использование сессии новым клиентом.
- Запрет личных запросов без действительного Bearer.
- Сохранение интересов, онбординга и последних условий.
- Неизвестные категории, некорректные фильтры и передача лишнего userId.
- Идемпотентное избранное и удаление, неизвестные активности.
- Сохранение истории, устойчивый UUID, повтор PUT после установки chosen.
- Новые записи раньше старых, несколько записей одной активности, пагинация.
- Несовпадающие UUID, отсутствующие активности и даты без часового пояса.
- Изоляция двух пользователей при чтении, обновлении, удалении и совпадающем UUID истории.
- Очистка истории с сохранением интересов и избранного.
- Повторная миграция и seed с сохранением личных данных.
- Реальные ограничения целостности PostgreSQL.
- Понятный 503 при недоступной базе без DSN и технической трассировки.
- CORS для разрешённого origin.

По умолчанию соединение для создания тестовой базы берётся из `backend/.env`. Можно задать `TEST_DATABASE_URL` отдельного тестового сервера. Тестовой роли необходимы права создания базы.

## Браузерные сценарии

`npm run test:e2e` собирает демоверсию независимо от настроенного API и проверяет девять сценариев: полный путь пользователя; пропуск интересов и границы формы; пустую выдачу; сохранение и офлайн-работу после загрузки; исчерпание серии; ошибки записи избранного и истории с повтором; повреждённое хранилище; экран 320 px; вкладки, карточки, удаление и возврат назад.

`npm run test:remote-ui` собирает серверную версию и проверяет три сценария:

1. Недоступный API: ошибка, повтор и только явный переход в деморежим.
2. Реальная связка приложение → FastAPI → PostgreSQL: интересы, фильтры, рекомендация, «Другое», избранное, chosen, перезапуск, прежний токен, повтор условий, «Удиви меня», удаление и очистка. Дополнительные HTTP-запросы подтверждают серверные данные.
3. Ошибка HTTP-записи и успешная повторная попытка; переход в деморежим с отдельными данными и возвращение к прежней серверной сессии.

Для live-сценариев сначала запустите API и PostgreSQL. API по умолчанию `http://127.0.0.1:8000`, другой адрес — `TEST_API_URL`. Разрешите origin `http://127.0.0.1:4174` в CORS. Каждый сценарий создаёт свою анонимную сессию; браузерные тесты не удаляют всю базу.

## Ручная проверка

- [ ] Запустить API/PostgreSQL, открыть `/health` и `/docs`.
- [ ] Настроить `EXPO_PUBLIC_API_URL` для браузера, эмулятора или LAN-адреса телефона.
- [ ] Запустить Expo с `--clear`, пройти или пропустить интересы.
- [ ] Задать 3 участника, 2 часа, 500 ₽, дома и спокойное настроение.
- [ ] Проверить ограничения и причины выбора, затем несколько раз нажать «Другое».
- [ ] Сохранить занятие, открыть избранное и удалить его.
- [ ] Отметить занятие через «Займусь этим», открыть соответствующую запись истории.
- [ ] Полностью закрыть приложение и открыть снова; интересы, история, избранное и серверная сессия сохраняются.
- [ ] Повторить подбор через форму и проверить «Удиви меня» без прошлых ограничений.
- [ ] Проверить системную кнопку «Назад» Android, жест iOS, safe area и увеличенный шрифт.
- [ ] Очистить историю с подтверждением; интересы и избранное сохраняются.
- [ ] Остановить API; увидеть понятную ошибку и повторную попытку.
- [ ] Явно перейти в деморежим, проверить раздельные данные, затем вернуть серверный режим.
- [ ] Проверить два чистых клиентских хранилища: личные данные не пересекаются.
- [ ] На установленной мобильной сборке проверить локальный режим без интернета; для первого получения пакета Expo Go нужен Metro.
